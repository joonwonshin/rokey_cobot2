# Plan: 음성 지정 협동 pick — YOLO 타겟팅 + GraspGenX + MoveIt 동적 회피

**작성:** 2026-08-05 (같은 날 3차 개정 — 음성 지정·동적 회피 요구 반영)
**시나리오:** 마트 계산대. 물체는 정지해 있다. **사람이 음성으로 물체를 지정**하고,
로봇이 그것만 집는다. 사람이 **경로에 끼어들면 로봇이 피한다.**

> ⛔ **이 계획의 한 문장:** 음성 타겟팅은 **이 워크스페이스에 이미 있고**,
> 그 덕분에 손 배제·물체 식별·마스크 생성이 **한꺼번에** 풀린다. 새로 만들 건 두 개뿐이다 —
> **YOLO 마스크 → GraspGenX 다리**와 **실행 중 재계획**.

## 0. 이미 있는 것 (2026-08-05 소스 확인) — 다시 만들지 않는다

| 자산 | 실체 | 역할 |
|---|---|---|
| `voice_processing/get_keyword.py` | STT + wakeup word + 키워드 추출 | 음성 → **target 이름** |
| `od_msg/srv/SrvDepthPosition` | `string target` → `float64[] depth_position` | 이름 → 위치 계약 |
| `object_detection/detection.py` | `get_3d_position` 서비스, YOLO 백엔드 | **이름으로 물체를 특정** |
| `object_detection/yolo.py` | `yolov8n_tools_0122.pt` + `class_name_tool.json` | 검출 모델 (⚠️ **공구용**) |
| MoveIt + Octomap + self-filter | `sensors_3d.yaml`, `octomap_frame: base_link`, `resolution: 0.02` | **2026-08-03 실기 검증 완료** |

**즉 "음성으로 지정한 물체를 집는다"는 이미 돌아가는 파이프라인이다.**
이번 작업은 그 안에서 **위치 추정을 grasp 생성으로 격상**하고 **동적 회피를 붙이는 것**이다.

## 1. 아키텍처 — 음성 지정이 세 문제를 동시에 푼다

```
"사과 집어줘" ─► [voice_processing] ─► target="apple"
                                          │
                                          ▼
                        [YOLO-seg] ─► target 클래스의 **인스턴스 마스크** (H,W)
                                          │
                     depth(float32 m) + K + 그 마스크 하나
                                          ▼
                  GraspGenX infer_scene_depth → {id: (grasps, conf)}  카메라 프레임
                                          │
                  G_base = T_base_cam · G_cam      (tf2 lookup)
                                          │
                  필터: conf / 도달 / 접근축 / **Octomap 충돌** / RG2 폭
                                          ▼
                       MoveIt pick ─► 실행 중 감시 ─► 사람 끼어들면 정지·재계획
```

### 음성 지정이 공짜로 해결하는 것

1. **물체 식별** — 어느 인스턴스를 집을지 클러스터링으로 추측할 필요가 없다. 이름이 정한다
2. **손 배제** — **지정한 물체의 마스크만 GraspGenX에 넣는다.** 사람 손은 마스크에 애초에 안 들어간다.
   2차 개정에서 설계했던 "장면 안정 대기 + ROI 컷"이 **안전 요구에서 편의 기능으로 격하**된다
3. **다물체 혼재** — 여러 개가 놓여 있어도 대상은 하나다. DBSCAN이 붙은 물체를 나누든 말든 상관없다

> 📌 **마스크 소스가 세 번 바뀐 것에 대해.** 규칙은 하나다 — **"무엇을 집을지 어떻게 정하느냐"가 마스크 소스를 정한다.**
> 임의 물체면 DBSCAN, 이름으로 지정하면 **이름을 아는 검출기**가 마스크를 내야 한다.
> 음성 지정이라는 새 정보가 들어왔으므로 YOLO가 맞다. DBSCAN은 **YOLO가 모르는 물체의 폴백**으로만 남긴다(지금은 안 만든다).

## 1-2. 카메라는 한 대로 충분하다 — 대신 octomap과 대상 물체가 싸운다

**YOLO-seg 때문에 카메라를 늘릴 필요는 없다.** 지금 D435i 한 대가 내는 토픽을 **셋이 각자 구독**할 뿐이다:

```
D435i (base 고정, TF 캘리브 완료)
  ├─ depth ─────────► MoveIt PointCloudOctomapUpdater   (장애물 맵)
  ├─ depth + K ─────► GraspGenX                          (grasp 생성)
  └─ color ─────────► YOLO-seg                           (대상 마스크)
```
같은 스트림을 여러 노드가 구독하는 건 ROS에서 비용이 아니다. **추가 하드웨어·추가 캘리브 0.**

### ⚠️ 진짜 문제: 대상 물체도 octomap에 장애물로 들어간다

장애물 회피를 켜는 순간 **집으려는 물체 자체가 장애물이 된다.** 그리퍼가 접근하면 MoveIt이
"충돌"이라며 계획을 거부한다. **이건 설계 결함이 아니라 pick 파이프라인이 항상 푸는 문제**이고,
회피를 메인으로 세우는 순간 반드시 만난다. 대응 순서:

1. **대상 물체를 `CollisionObject`로 planning scene에 등록**하고, 접근·파지 구간에서
   그리퍼 링크와 그 물체 사이 충돌을 **ACM(허용 충돌 행렬)로 허용**한다 — 표준 방식
2. octomap에서 대상 물체 영역을 빼는 방법도 있으나, 마스크가 있으니 1번이 더 깔끔하다
3. **집은 뒤에는 `attached object`로 붙여** 들고 이동할 때 자기 손의 물체를 장애물로 보지 않게 한다

**Phase 0에서 반드시 확인한다.** 이걸 안 하면 "회피는 되는데 집지를 못하는" 상태가 된다.

### eye-to-hand(현재) vs eye-in-hand — 지금은 바꾸지 않는다

| | **eye-to-hand (고정, 현재)** | eye-in-hand (손목 장착) |
|---|---|---|
| **octomap** | ✅ **이것만 가능하다.** 시점이 고정이라 맵이 안정 | ❌ 팔이 움직이면 시점이 바뀌어 맵이 흔들린다 |
| 반응성 | ✅ 항상 보고 있다 — 놓자마자 인식 | ❌ 팔을 그쪽으로 보내야 보인다 |
| depth 정밀도 | ❌ 멀어서 낮다 | ✅ 가까이 가서 본다 |
| 캘리브 | ✅ 1회, 정적 TF (**이미 완료**) | ❌ AX=XB, 케이블·무게 추가 |
| self-occlusion | ❌ 접근 시 팔이 물체를 가림 | ✅ 없음 |

**결론: 지금 시나리오는 eye-to-hand 한 대가 맞다.**
- octomap이 **메인 시연**이고, 그건 고정 카메라가 아니면 성립하지 않는다
- self-occlusion은 "**잡기 직전 1회 계산 후 open-loop 접근**" 설계라 문제가 안 된다 (물체가 정지해 있다)
- 두 번째 카메라(eye-in-hand)는 **정확도가 부족하다고 실측된 뒤에** 최종 정렬용으로 검토한다.
  지금 넣으면 캘리브·배선·동기화가 늘고 얻는 건 아직 없다

## 1-3. 최종 grasp를 **누가** 정하는가 — 책임 사슬

| # | 담당 | 입력 → 출력 | 프레임 |
|---|---|---|---|
| 1 | `voice_processing` (**기존**) | 음성 → `target` 문자열 | — |
| 2 | YOLO-seg (**기존 노드 모델 교체**) | color → 대상 물체 마스크 `(H,W)` | 이미지 좌표 |
| 3 | **GraspGenX** | depth(m) + K + 마스크 → **grasp 후보 K개 `(K,4,4)` + conf `(K,)`** | **`camera_color_optical_frame`** |
| 4 | **우리 브리지 노드** (신규) | tf2 `base_link ← camera_color_optical_frame` 적용 | **`base_link`** |
| 5 | **우리 선택 정책** (신규) | conf·도달거리·접근축·충돌·RG2 폭 → **최종 1개** | `base_link` |
| 6 | **우리 그리퍼 프레임 변환** (신규) | GraspGenX 그리퍼 규약 → 로봇 TCP/flange | `base_link` |
| 7 | MoveIt | 최종 pose → **IK + 궤적** (pre-grasp → grasp → lift) | joint space |
| 8 | 실행 감시 (신규) | 궤적 실행 + 충돌 감시 → stop/재계획 | — |

**"최종 grasp를 정하는 곳"은 5번이고, 그건 우리가 짜야 한다.**
GraspGenX는 **후보만** 준다(어느 게 좋은지 순위는 주지만 "이걸 써라"는 말은 안 한다).
MoveIt은 **도달 가능한지만** 본다(어느 후보가 과제에 적합한지 모른다).
그 사이의 판단은 **아무도 대신 해주지 않는다.** = Phase 0-D.

### 6번이 조용히 틀리는 지점이다

GraspGenX의 grasp 4×4는 **자기 그리퍼 규약**의 포즈다. RG2 config에서 뽑은
`offset_open=[0, 0, 0.175]`, `fingertip_depth=0.18`이 그 규약을 정의한다.
MoveIt은 **로봇의 end-effector 링크** 기준으로 계획한다. **둘 사이 정적 변환을 한 번 확정해야 한다.**

- 이 변환이 틀리면 → **grasp가 물체를 뚫거나 허공을 집는다** (§6 분기 F가 바로 이것)
- 부호 하나로 18 cm가 어긋난다
- **RViz에서 그리퍼 메시를 grasp 위치에 띄워 눈으로 확인한 뒤에만 실기로 간다**

## 2. 새로 만드는 것 두 개

### A. YOLO 마스크 → GraspGenX 다리

**⚠️ 현재 모델은 공구용(`yolov8n_tools_0122.pt`)이라 마트 품목을 모른다.** 선택지:

| 안 | 내용 | 비용 |
|---|---|---|
| **A-1 (권고)** | **COCO 기본 `yolov8n-seg.pt`** — `apple` `banana` `orange` `bottle` `cup` `bowl` 등이 이미 있다 | **학습 0.** 시연 품목을 COCO 클래스에 맞춰 고르면 끝 |
| A-2 | 기존 공구 데이터셋으로 시연 | 학습 0. 단 "마트 계산대" 연출이 깨진다 |
| A-3 | 마트 품목 재학습 | 라벨링+학습. **마지막 수단** |

**핵심: bbox가 아니라 segmentation 마스크를 쓴다.** bbox를 그대로 `instance_mask`로 넣으면
상판 픽셀이 섞여 **테이블을 집는 grasp**가 나온다. `-seg` 모델이면 진짜 마스크가 나온다.
`-seg`를 못 쓰면 bbox 안에서 평면 제거를 한 번 더 돌린다.

```python
# ponytail: 마스크 하나만 넘긴다. GraspGenX는 다물체를 받지만 대상은 이미 정해져 있다
mask = np.zeros(depth.shape, np.int32)
mask[yolo_seg_mask] = 1
grasps = client.infer_scene_depth(depth_m, K, mask, RG2_SWEEP)[1]
```

### B. 실행 중 동적 회피 ← **여기가 이번 개정의 진짜 새 작업**

**현재 상태:** Octomap + self-filter는 실기 검증됐다(2026-08-03). 즉 **계획 시점 회피는 이미 된다** —
사람이 미리 서 있으면 그 사람을 피해 경로를 짠다.

**빈 곳:** MoveIt `move_group`은 **실행 중에 재계획하지 않는다.** 궤적을 끝까지 밀어붙인다.
"경로에 끼어들면 피한다"는 이 빈 곳을 메우는 작업이다.

| 안 | 동작 | 난이도 | 시연에서 보이는 것 |
|---|---|---|---|
| B-1a | stop → **장애물이 사라질 때까지 대기** → 재개 | 낮음 | 로봇이 **멈췄다 기다린다.** 수동적이다 |
| **B-1b (권고)** | stop → **즉시 재계획** → 새 경로가 있으면 **우회 실행**, 없으면 대기 | **B-1a와 거의 같음** | **장애물이 남아 있어도 다른 길로 돌아간다** ← "피한다"가 실제로 보인다 |
| B-2 | 궤적을 짧은 구간으로 쪼개 구간마다 재계획 (receding horizon) | 중간 | 정지 없이 **부드럽게 우회** |
| B-3 | MoveIt Servo 실시간 회피 | 높음. 새 스택 + 실기 튜닝 | 가장 인상적. **시간이 남을 때만** |

**B-1a가 아니라 B-1b로 간다.** 어차피 재개하려면 재계획을 부른다 —
**재개 조건을 "장애물이 사라지면"이 아니라 "새 경로가 나오면"으로 바꾸는 것뿐이다.**
구현 비용은 거의 같은데, 로봇이 **기다리는 것**과 **돌아가는 것**은 시연에서 완전히 다르다.

### B-0. 그런데 「피한다」의 8할은 **이미 된다**

계획 시점 회피는 2026-08-03에 실기 검증됐다. **장애물을 놓고 집으러 보내면 지금도 우회한다.**
"피하는 것"을 메인으로 세운다면 **가장 값싸고 확실한 그림은 대비(對比)다:**

```
같은 물체를 두 번 집는다
  ① 장애물 없음 → 거의 직선 경로
  ② 같은 자리에 박스를 놓음 → 위로/옆으로 크게 우회
RViz에 두 궤적을 겹쳐 띄우면 "피했다"가 설명 없이 보인다
```

**이건 새 코드 0줄이다.** B-1b는 여기에 "실행 중에 놓아도 된다"를 더하는 것이다.

**시연용 장애물 고르는 법 (depth에 안 보이면 octomap에 안 뜬다):**
- ✅ 크고 무광인 박스, 밝은 색
- ❌ 얇은 막대, 검은 물체, 투명·반사체 — **D435i가 못 본다.** 시연 중에 "왜 안 피하지"가 된다
- 최소 크기는 `octomap_resolution: 0.02` 기준 **몇 셀 이상**이어야 한다 → 실측으로 하한을 잡는다

**전제 확인 필요 (⚠️ 미검증):**
- 사람 팔이 depth에 들어온 뒤 **octomap에 반영되기까지의 지연**
- 사람이 빠진 뒤 **셀이 지워지는 속도** — 안 지워지면 로봇이 계속 막혀 있다
- self-filter가 사람 팔을 로봇 팔로 오인하지 않는지

## 3. Phase

### Phase 0 · 지금, 이 랩탑 (GPU·로봇 불필요, 예상 4h)

- **A. YOLO-seg 교체 확인** — `yolov8n-seg.pt`로 `apple` bag을 돌려 사과 마스크가 나오는지.
  ultralytics는 이미 설치돼 있다(`object_detection`이 쓴다)
- **B. GraspGenX 클라이언트 + `--fake`** — 어제 계획 §2-B 그대로
- **C. 좌표 변환** — `tf2` lookup. **npy 직접 로드 금지** (2026-08-02 90° 오류 이력)
- **D. grasp 필터 + RG2 폭** — `conf` / `norm(t)<0.900` / `g[2,2]<-0.3` / 충돌 / `rgwd = round(w*10000)`
- **E. 회피 감시 노드 골격** — planning scene 충돌 감지 → stop → 재계획. **가짜 장애물로 검증**
- **F(신규). 그리퍼 프레임 변환 확정** — GraspGenX 그리퍼 규약 ↔ 로봇 end-effector 링크.
  **RViz에 그리퍼 메시를 grasp 위치에 띄워 눈으로 확인한다.** 부호 하나로 18 cm가 어긋난다(§1-3)
- **G(신규). 대상 물체 ACM 처리** — 대상을 `CollisionObject`로 등록하고 접근·파지 구간에서
  그리퍼-물체 충돌을 허용, 집은 뒤 `attached object`로 전환. **안 하면 회피는 되는데 집지를 못한다**(§1-2)

**DoD:**
1. `apple` bag에서 target="apple" 마스크가 나오고 `--fake` grasp가 RViz `base_link`에서 사과 위에 뜬다
2. **`hand` bag에서 target 마스크에 손이 섞이지 않는다** — 음성 지정의 손 배제 효과 확인
3. 가짜 장애물을 경로에 넣으면 감시 노드가 stop을 부르고, 치우면 재개한다

**셀프체크:** `test_grasp_transform.py` — 단위행렬과 알려진 grasp로 항등 `assert`.

### Phase 1 · GPU 세션 (90분)

GraspGenX 서버 → `--fake` 해제 → 추론 시간 측정.
**판정선은 절대값이 아니라 총 체감 지연에서의 비중이다**(§4).
⚠️ 이 랩탑 GPU는 RTX 4060 Laptop **8GB**([[ws/cobot2/context/constraints]]) — `num_grasps`는 **64**로 시작한다(12GB 가정 아님).

### Phase 2 · 실기 — 회피 검증 (로봇 필요, 사용자 승인 필수)

**회피가 메인 시연이므로 여기가 가장 중요한 Phase다.** 순서를 지킨다:

1. **모션 없이 — 장애물 실측** (로봇 정지)
   박스를 넣었다 뺐다 하며 `/monitored_planning_scene`에서
   ① octomap 반영 지연 ② **제거 후 셀이 지워지는 시간** ③ **검출되는 최소 장애물 크기**를 잰다.
   ③이 시연용 소품을 정한다
2. **B-0 대비 시연** — 장애물 유/무로 같은 pick을 두 번. **새 코드 없이 되는지 먼저 확인**
3. **재계획 시간 측정** — B-1b의 정지 구간 길이를 결정한다. `state.md`의 "OMPL 병목 미측정"이
   여기서 **시연 품질에 직접 걸린다.** 계획이 2초 걸리면 로봇이 2초 멈춰 있는다
4. **B-1b 저속 검증** — 사람이 아니라 **박스로 먼저**. 사람은 마지막

**DoD:** 실행 중 박스를 경로에 넣으면 로봇이 멈추고, **박스를 그대로 둔 채 다른 경로로 우회해 물체에 도달**한다.

### Phase 3 · 통합 시연

음성 → 지정 → grasp → pick, 도중 끼어들기 → 정지 → 재개.

### Phase 4 · FoundationPose (조건부)

품목이 고정되고 **배치 방향이 중요**해질 때만(세워서 담기, 라벨 방향).
그때는 해당 품목만 메시 스캔 + grasp 사전계산으로 간다.

## 4. 속도와 정확도 — 무엇을 재나

**체감 지연 = STT + YOLO + GraspGenX + MoveIt 계획 + 모션.**
음성 시나리오에서는 **STT가 가장 큰 항일 가능성이 높다.** 인식 200ms 최적화는 그 다음 문제다.
→ **먼저 구간별로 재고, 그 다음에 고친다.**

**정확도 지배 항 (순서대로):**
1. **hand-eye 캘리브레이션** — **카메라를 재배치하면 이전 캘리브는 전부 무효다. 재배치 직후 재캘리브가 1순위.**
2. 마운트 강성 — 재캘리브가 이미 "강성 확보 후"로 미뤄져 있다
3. depth 품질 (상판 반사)
4. 그 다음이 grasp 생성 품질

## 6. 실패 분기

| 분기 | 증상 | 조치 |
|---|---|---|
| A | YOLO가 시연 품목을 못 잡음 | COCO 클래스로 품목 교체(A-1) → 안 되면 재학습(A-3) |
| B | grasp가 상판을 집음 | **bbox를 마스크로 쓰고 있다.** `-seg` 모델로 바꾸거나 bbox 안 평면 제거 |
| C | 사람이 빠져도 로봇이 계속 막힘 | octomap 셀이 안 지워지는 것. ray-casting clearing 파라미터 확인. 최후엔 주기적 clear |
| D | 실행 중 stop이 안 걸림 | 감시 주기 < octomap 갱신 주기인지. 감시가 더 느리면 의미 없다 |
| E | grasp가 0개 | `grasp_threshold` 0.7→0.3. 그래도 0이면 좌표 프레임 의심 |
| F | grasp가 물체를 뚫음 | `fingertip 0.18m` 부호. **RViz에서만 확인, 실기 금지** |
| **G** | **장애물을 놨는데 안 피함** | 코드가 아니라 **소품을 먼저 의심한다.** RViz octomap에 셀이 떴는지 확인 — 안 떴으면 D435i가 못 본 것(얇음·검정·반사). 크고 무광인 박스로 교체 |
| H | 우회 경로가 안 나옴 (계속 정지) | 장애물이 작업공간을 실제로 막고 있는 것일 수 있다. 시연 동선에서 **우회 여유가 있는 위치**에 장애물을 둔다. 그 다음이 플래너 시간 증가 |
| I | 장애물이 대상 물체를 가림 | YOLO 마스크가 사라져 grasp가 통째로 없어진다. **마지막 유효 grasp를 잠그고** 진행하거나(정지 물체이므로 타당) 동선을 바꾼다 |
