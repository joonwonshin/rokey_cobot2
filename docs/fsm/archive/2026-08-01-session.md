토픽 리스트 확인했다. 세 가지 고칠 게 있다.

1. 런치 명령 — 녹화용으로 두 개 끄고 하나 맞춰라

ros2 launch realsense2_camera rs_align_depth_launch.py \
  depth_module.depth_profile:=848x480x30 \
  rgb_camera.color_profile:=848x480x30 \
  initial_reset:=true \
  align_depth.enable:=true \
  pointcloud.enable:=false \
  enable_rgbd:=false
변경	이유
color 1280x720 → 848x480	align_depth는 컬러 해상도로 depth를 리샘플한다. 1280×720이면 aligned depth가 55MB/s(3.3GB/분)로 뛴다. 맞추면 24MB/s. Octomap·플래너 개발에 720p depth는 과잉
pointcloud.enable:=false	/depth/color/points는 390MB/s. 게다가 depth+camera_info로 언제든 재생성 가능한 파생물이다. 녹화 세션엔 CPU만 먹는다
enable_rgbd:=false	/rgbd 합본 메시지. 개별 토픽 다 녹화하니 중복
initial_reset:=true	유지. USB 인식 꼬임 방지
컬러 848로 내리는 게 싫으면 1280 그대로 두고 aligned depth를 빼면 된다. 다만 Day4 ray-plane(컬러에서 검출→해당 픽셀 depth)에 aligned가 필요하니, 그 경우엔 raw depth + extrinsics/depth_to_color로 직접 계산해야 한다.

2. 녹화 토픽

ros2 bag record --compression-mode file --compression-format zstd \
  -o d435i_$(date +%m%d_%H%M) \
  /camera/camera/depth/image_rect_raw \
  /camera/camera/depth/camera_info \
  /camera/camera/aligned_depth_to_color/image_raw \
  /camera/camera/aligned_depth_to_color/camera_info \
  /camera/camera/color/image_raw/compressed \
  /camera/camera/color/camera_info \
  /camera/camera/extrinsics/depth_to_color \
  /tf /tf_static
뺀 것: depth/color/points(파생물·초대용량), */theora·*/compressedDepth(재생 시 안 풀리는 경우 잦음), */metadata, color raw
color_info는 반드시 포함 — 없으면 compressed 컬러가 쓸모없어진다
대략 50MB/s → zstd 후 1.5~2GB/분. 60초 × 5장면
토픽 이름은 런치 명령이 정하지 마운트 방식이 정하지 않는다. eye-in-hand → eye-to-hand로 바꿔도 위 이름은 그대로고, 바뀌는 건 TF 부모 프레임뿐이다. 위 런치를 쓰는 한 이 리스트는 유효하다.

3. 마운트가 헐거운 건 — 생각보다 문제 없다, 단 한 가지만 빼고
캘리브 정확도는 마운트 강성에 통째로 종속된다. 헐거우면 mm 단위 정확도는 오늘 못 얻는다. 그런데:

Octomap·OMPL·상태머신·ray-plane 로직 개발 → 대충 맞는 TF면 충분. 영향 없음
Day4 ray-plane 정확도 실측 → 의미 없다. 마운트 확정될 때까지 미뤄라. 헐거운 마운트에서 오차 재고 코드 부호 만지는 건 시간 낭비다
그러니 오늘은 "잠정 캘리브"로 찍고 넘어가라. 대신 두 가지만:

마운트 위치를 마스킹 테이프로 표시 + 사진 — 나중에 재현·비교 가능하게
bag 녹화와 캘리브를 같은 세션에서, 카메라 안 건드리고 연속으로 — 둘 사이에 움직이면 짝이 안 맞는다
.calib 파일명에 _provisional 붙여두는 걸 권한다.
